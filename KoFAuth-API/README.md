# KoFAuth-API

Контракты платформы авторизации: доменная модель, DTO, интерфейсы репозиториев и
сервисов, доменные события, конфигурация.

**Модуль не содержит реализаций.** Его собирают Paper, Velocity, Spring Boot, JDA и
Telegram Bot API — единственная внешняя зависимость здесь `slf4j-api`. Любая другая
библиотека в этом модуле рано или поздно столкнётся версиями с одной из платформ.

---

## Пакеты

| Пакет | Содержимое |
|-------|-----------|
| `model` | Доменные сущности: `Account`, `Session`, `Device`, `AuthToken`, `IpAddress`, перечисления |
| `dto` | Объекты для внешнего мира: `AuthContext`, `LoginRequest`, `AccountProfileDto`, … |
| `result` | Типизированные исходы: `OperationResult<T>`, `AuthResult`, `RegistrationResult` |
| `repository` | 14 контрактов доступа к данным, все методы асинхронные |
| `service` | 10 контрактов бизнес-логики |
| `event` | `EventBus` и доменные события |
| `config` | `ConfigurationService`, `Reloadable`, `ConfigFile` |
| `exception` | `KoFAuthException` и наследники |

Точка входа — `KoFAuth`: фасад, отдающий все службы. Там, где внедрить зависимость
нельзя (команды Bukkit, слушатели платформы), доступен `KoFAuthProvider.get()`.

## Пять решений, определяющих этот модуль

### 1. Исключения — только для сбоев инфраструктуры

Неверный пароль, занятый ник, истёкший код — штатные исходы, они возвращаются
значением, а не бросаются:

```java
AuthResult result = auth.login(request).join();
switch (result.type()) {
    case SUCCESS -> sendToLobby(result.session());
    case TWO_FACTOR_REQUIRED -> promptForCode(result.requiredTwoFactor());
    case BAD_PASSWORD -> tellRemaining(result.remainingAttempts());
    // компилятор потребует разобрать остальные исходы
}
```

`KoFAuthException` летит, только когда упала база или повреждена конфигурация.

### 2. Весь ввод-вывод асинхронный

Каждый метод репозитория и сервиса возвращает `CompletableFuture`. Обращение к MySQL
из главного потока Minecraft останавливает тик всего сервера; при 5 000 игроков одна
синхронная выборка на входе — заметный фриз для всех.

Возврат в главный поток делает платформенный модуль:

```java
auth.authentication().login(request)
    .thenAcceptAsync(result -> player.sendMessage(render(result)), mainThreadExecutor);
```

### 3. Доменная сущность не покидает процесс

`Account` содержит `passwordHash` и полный IP. Наружу — в REST, боты, личный кабинет —
уходит `AccountProfileDto`: без хэша, с маскированным адресом. Разделение
принудительное, а не по договорённости: в DTO этих полей просто нет.

Той же цели служат переопределённые `toString()`: `Account`, `AuthToken`, `TotpSecret`,
`LoginRequest` и `TotpSetupDto` печатают `<redacted>` вместо секретов. `IpAddress.toString()`
возвращает маскированный адрес — полный доступен явным вызовом `asString()`.

### 4. `IpAddress` вместо строки

Строковое представление адреса неоднозначно: `::1` и `0:0:0:0:0:0:0:1` — один адрес,
но разные строки, и агрегация по IP на строках даёт ложные несовпадения. Тип хранит
байты (как колонка `VARBINARY(16)`), умеет считать подсеть для AntiBot и маскировать
адрес для показа.

### 5. Инварианты проверяются в конструкторе

`Session` не даст создать себя с жёстким потолком раньше скользящего срока,
`Device` — с отпечатком не длины SHA-256, `TotpSecret` — с числом цифр вне 6..8.
Ошибка обнаруживается там, где допущена, а не тремя слоями ниже.

## Тесты

```bash
./mvnw -pl KoFAuth-API test
```

119 тестов. Покрыты классы, содержащие логику, а не только поля:
`IpAddress` (разбор, маскирование, подсети, неизменяемость), `AuthState` (матрица
переходов), `Role` (маски прав), `Session` (два срока жизни), `Account`,
`AuthToken` (ротация и повторное использование), `CaptchaChallenge`, `OperationResult`.
