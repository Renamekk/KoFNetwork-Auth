# KoFAuth — установка на сервер

Инструкция для того, кто ставит сеть с нуля. Ничего, кроме доступа по SSH,
не требуется: Java, Maven, MySQL, Redis и серверные ядра ставить руками не нужно —
всё поднимается в Docker одной командой.

Кто торопится: [раздел 3](#3-установка-одной-командой) — это буквально три строки.

---

## 1. Что вы получите

После установки на сервере работает:

| Что | Где |
|---|---|
| Прокси Velocity — точка входа игроков | порт `25565` |
| Limbo на Paper — где игрок сидит до входа | внутри, наружу не смотрит |
| Лобби на Paper — куда игрок попадает после входа | внутри, наружу не смотрит |
| MySQL + Redis | внутри, наружу не смотрят |
| REST API + личный кабинет + Swagger | порт `8080` или HTTPS на вашем домене |
| Telegram- и Discord-боты | по желанию |

Игрок заходит на `ваш-ip:25565`, попадает в Limbo, регистрируется командой
`/register пароль пароль` и автоматически переносится в лобби. Всё остальное —
почта, 2FA, привязки, личный кабинет — включается по мере надобности и
работать сети не мешает.

## 2. Что нужно подготовить

### 2.1 Сервер

| Параметр | Минимум | Рекомендуется |
|---|---|---|
| ОС | Ubuntu 22.04 / Debian 12, x86_64 | Ubuntu 24.04 |
| Память | 4 ГБ | 8 ГБ |
| Ядра | 2 | 4 |
| Диск | 20 ГБ | 40 ГБ SSD |

На 4 ГБ уменьшите в `.env` память лобби: `HEAP_LOBBY=1G`.

**Про ядра.** Проверка пароля BCrypt при стоимости 12 занимает 100–250 мс
процессорного времени. Это не «медленно», а сознательный выбор: ровно эта цена
делает перебор украденной базы дорогим. На двух ядрах сеть выдержит порядка
десяти входов в секунду — этого достаточно почти всем, но при массовом заходе
после рестарта очередь будет заметна.

### 2.2 Домен (необязательно)

Нужен только для HTTPS-кабинета. A-запись должна указывать на IP сервера.
Без домена кабинет доступен по `http://IP:8080` — работает, но пароли
поедут открытым текстом, поэтому для публичного использования домен лучше завести.

### 2.3 Токены (необязательно)

Telegram и Discord подключаются позже и в любой момент — см. [раздел 7](#7-telegram-бот)
и [раздел 8](#8-discord-бот). Ставить систему без них можно.

## 3. Установка одной командой

Подключитесь к серверу и выполните:

```bash
sudo apt update && sudo apt install -y git
git clone https://github.com/Renamekk/KoFNetwork-Auth.git
cd KoFNetwork-Auth/deploy
./install.sh
```

Всё. Скрипт сам:

1. поставит Docker, если его нет;
2. создаст `.env` и **сгенерирует все пароли и ключи** — придумывать их не нужно;
3. соберёт jar внутри контейнера (Java и Maven на сервере не понадобятся);
4. поднимет стек и дождётся, пока каждая служба станет здоровой;
5. напечатает адреса и следующие шаги.

Первый запуск занимает 10–20 минут: скачиваются образы, зависимости Maven и
серверные ядра, Paper генерирует мир лобби. Повторные — около минуты.

Скрипт спросит три необязательные вещи (токен Telegram, токен Discord, домен).
Любую можно пропустить, нажав Enter, и настроить позже. Чтобы не спрашивал
ничего — `./install.sh --yes`.

### Если файлы уже у вас на компьютере

```bash
# с локальной машины, из каталога с проектом
rsync -avz --exclude target --exclude .git ./ user@СЕРВЕР:/opt/kofauth/
ssh user@СЕРВЕР 'cd /opt/kofauth/deploy && ./install.sh'
```

> **Если копируете с Windows** — убедитесь, что перевод строки в `.sh` остался
> LF. В репозитории это закреплено файлом `.gitattributes`, но копирование
> через некоторые FTP-клиенты в текстовом режиме всё портит. Признак беды:
> `bash: ./install.sh: /usr/bin/env^M: No such file or directory`.
> Лечится `sed -i 's/\r$//' deploy/*.sh`.

## 4. Открыть порты

```bash
sudo ufw allow 22/tcp        # SSH — сначала, иначе закроете себе доступ
sudo ufw allow 25565/tcp     # Minecraft
sudo ufw allow 80,443/tcp    # только если используете домен и HTTPS
sudo ufw allow 8080/tcp      # только если домена нет и кабинет нужен снаружи
sudo ufw enable
```

MySQL и Redis наружу **не публикуются вовсе** — они видны только контейнерам
внутри сети Docker. Это не перестраховка: открытый в интернет MySQL с любым
паролем находят сканеры за часы.

## 5. Проверка после установки

```bash
cd /путь/к/KoFNetwork-Auth/deploy
./kofauth.sh status
```

Все службы должны быть `running (healthy)`. Дальше — зайдите в игру на
`IP-сервера:25565` клиентом 1.21.x и пройдите сценарий:

| Действие | Ожидаемо |
|---|---|
| Заход новым ником | Пустой мир, подсказка «Зарегистрируйтесь» |
| Написать в чат | Сообщение не проходит |
| `/help` | Команда отклонена |
| Сломать блок | Блок цел |
| `/register МойПароль1 МойПароль1` | Аккаунт создан, перенос в лобби |
| Выйти и зайти снова | Пароль не спрашивают — действует сессия |
| `/login неверный` трижды | Временная блокировка |

Кабинет: `http://IP:8080` (или `https://ваш-домен`). Документация API —
`/swagger-ui.html`.

Если что-то не так — [раздел 12](#12-если-что-то-не-работает).

## 6. Права администратора

Аккаунт получают в игре, права — командой на сервере:

```bash
./kofauth.sh admin ВашНик
```

Проверка: в игре `/auth info` покажет состояние базы, кэша и пулов.

Полный список подкоманд `/auth` — в [03-DEPLOYMENT.md](03-DEPLOYMENT.md#9-административные-команды).
Их можно выполнять и из консоли прокси, у неё все права безусловно:

```bash
./kofauth.sh console
# > auth resetpassword Ник НовыйПароль1
# выход без остановки сервера: Ctrl-P, затем Ctrl-Q
```

Роль `owner` даёт сверх `admin` право выгружать и загружать данные
(`auth export`, `auth import`): `./kofauth.sh admin ВашНик owner`.

## 7. Telegram-бот

Даёт игрокам вход подтверждением кнопки и уведомления о чужих входах.

1. Напишите [@BotFather](https://t.me/BotFather) → `/newbot` → задайте имя.
2. Скопируйте выданный токен вида `1234567890:AAH...`.
3. На сервере:

```bash
cd deploy
nano .env
#   TELEGRAM_BOT_TOKEN=сюда токен
#   TELEGRAM_BOT_USERNAME=имя_бота_без_собачки
#   COMPOSE_PROFILES=telegram        (или bots — включит сразу и Discord)
./kofauth.sh start
```

Проверка: `./kofauth.sh logs telegram` → строка «Telegram-бот запущен».

Игрок привязывает аккаунт так: в игре `/telegram` выдаёт код, код отправляется
боту командой `/link КОД`. Только так: код выдаётся **в игре**, и это
единственный способ доказать, что аккаунтом владеет тот, кто пишет боту.

## 8. Discord-бот

1. [discord.com/developers/applications](https://discord.com/developers/applications)
   → **New Application**.
2. Вкладка **Bot** → **Reset Token** → скопируйте токен.
3. Вкладка **OAuth2** → **URL Generator** → scopes `bot`, `applications.commands`
   → откройте полученную ссылку и добавьте бота на свой сервер.
4. Скопируйте ID своего сервера Discord (правой кнопкой по значку сервера →
   «Копировать ID», нужен включённый режим разработчика).

```bash
nano .env
#   DISCORD_BOT_TOKEN=токен
#   DISCORD_GUILD_ID=id_сервера     (пусто — команды появятся глобально за час)
#   COMPOSE_PROFILES=telegram,discord
./kofauth.sh start
```

Slash-команды: `/profile`, `/link`, `/unlink`, `/login`, `/devices`, `/history`, `/security`.

Привязка та же, что у Telegram: в игре `/discord` выдаёт код, код отправляется
боту командой `/link КОД`. Направление именно такое, потому что владение игровым
аккаунтом можно доказать только внутри игры — иначе привязать чужой ник к своему
Discord смог бы любой, кто этот ник знает.

### OAuth2 — привязка Discord прямо с сайта

Нужен домен с HTTPS. В настройках приложения Discord → **OAuth2** → **Redirects**
добавьте `https://ваш-домен/api/discord/callback`, затем:

```bash
nano .env
#   DISCORD_OAUTH_ENABLED=true
#   DISCORD_OAUTH_CLIENT_ID=...
#   DISCORD_OAUTH_CLIENT_SECRET=...
#   DISCORD_OAUTH_REDIRECT_URI=https://ваш-домен/api/discord/callback
./kofauth.sh restart webapi discord
```

## 9. Почта

Без SMTP не работают: восстановление пароля, подтверждение адреса и письма о
подозрительных входах. Остальное работает.

```bash
nano .env
#   MAIL_ENABLED=true
#   SMTP_HOST=smtp.yandex.ru       (Gmail: smtp.gmail.com)
#   SMTP_PORT=587
#   SMTP_USERNAME=noreply@ваш-домен
#   SMTP_PASSWORD=пароль_приложения
#   MAIL_FROM=noreply@ваш-домен
./kofauth.sh restart webapi velocity
```

**Пароль приложения, а не пароль от почты.** У Gmail и Яндекса обычный пароль
для SMTP не подходит: нужен отдельный пароль приложения, выдаваемый в настройках
безопасности ящика. Его можно отозвать, не меняя основной пароль.

Проверка: в игре `/email вы@почта` — должно прийти письмо с кодом,
подтверждение `/email verify КОД`.

## 10. HTTPS и домен

Если при установке домен не указывали:

```bash
nano .env
#   DOMAIN=auth.example.com
#   ACME_EMAIL=вы@example.com
#   TRUST_PROXY_HEADER=true
#   WEBAPI_BIND=127.0.0.1
#   COMPOSE_PROFILES=web            (добавьте к уже включённым через запятую)
./kofauth.sh start
```

Сертификат Let's Encrypt Caddy получит и будет продлевать сам. Условия: A-запись
домена указывает на этот сервер, порты 80 и 443 открыты и свободны.

`WEBAPI_BIND=127.0.0.1` убирает порт 8080 из интернета: снаружи остаётся только
443, а HTTP-версия сама переадресуется на HTTPS.

`TRUST_PROXY_HEADER=true` включается **только вместе** с обратным прокси. Без него
KoFAuth берёт адрес сокета; с ним — заголовок, который без прокси подставит сам
клиент, обойдя и ограничение скорости, и привязку сессии к IP, и баны по адресу.

## 11. Повседневная работа

```bash
./kofauth.sh status          # что поднято
./kofauth.sh logs            # логи всех служб
./kofauth.sh logs velocity   # логи одной
./kofauth.sh console         # консоль прокси (команды auth)
./kofauth.sh stop            # остановить, данные сохраняются
./kofauth.sh start           # поднять обратно
./kofauth.sh restart lobby   # перезапустить одну службу
./kofauth.sh db              # консоль MySQL
./kofauth.sh backup          # дамп базы + копия .env в backups/
```

### Обновление

```bash
./kofauth.sh update
```

Подтянет изменения из git, пересоберёт jar и перезапустит службы в правильном
порядке: сначала веб-API (он применяет миграции), затем прокси, Limbo и лобби.

Схема развивается **только новыми** файлами миграций: `V1` и `V2` уже посчитаны
Flyway по контрольной сумме, и правка применённого файла остановит запуск.

### Резервные копии

```bash
./kofauth.sh backup
```

Кладёт в `backups/` дамп базы и копию `.env`. Обе части нужны вместе:

⚠️ **Дамп без `ENCRYPTION_KEY` наполовину бесполезен.** Секреты TOTP и токены
Discord зашифрованы AES-256-GCM. Восстановив базу с другим ключом, вы получите
аккаунты, у которых второй фактор не работает и штатным путём не отключается.

Ежедневная копия в 4 утра:

```bash
(crontab -l 2>/dev/null; echo "0 4 * * * cd $(pwd) && ./kofauth.sh backup >/dev/null 2>&1") | crontab -
```

И увозите `backups/` с сервера — копия, лежащая на том же диске, не переживёт
именно того события, ради которого делается.

Восстановление: `./kofauth.sh restore backups/kofauth-20260803-040000.sql.gz`

## 12. Если что-то не работает

### `./install.sh: Permission denied`

```bash
chmod +x deploy/*.sh
```

### `bash: ./install.sh: /usr/bin/env^M: No such file or directory`

Файлы скопированы с переводом строки Windows.

```bash
sed -i 's/\r$//' deploy/*.sh
```

### Служба не становится healthy

```bash
./kofauth.sh logs имя_службы
```

| Что в логе | Что означает |
|---|---|
| `Не удалось подключиться к базе` | MySQL ещё поднимается — подождите, healthcheck дождётся сам |
| `KoFAuth не запустился, плагин выключается` | Дальше в строке причина: обычно пустой `ENCRYPTION_KEY` или нет доступа к базе |
| `Redis недоступен, работаем без кэша` | Не смертельно: вход работает, но сессии перестают быть общими между процессами |
| Лобби долго стартует | Первый запуск генерирует мир, до 5 минут — это нормально |

### Игрока выкидывает при заходе на лобби

Значит, не совпал секрет форвардинга между Velocity и Paper. Он один для всех
и берётся из `FORWARDING_SECRET` в `.env`. После правки — `./kofauth.sh restart`.

### Игрока выкидывает сразу после входа

Смотрите `security_logs` на `SESSION_IP_MISMATCH` — обычно это мобильный интернет
со сменой адреса:

```bash
./kofauth.sh db "SELECT event_type, COUNT(*) FROM security_logs
                 WHERE created_at > DATE_SUB(UTC_TIMESTAMP(3), INTERVAL 1 HOUR)
                 GROUP BY event_type;"
```

Лечится `auth.session.bind-to-ip: false` в `data/config/config.yml`, но это
ослабляет защиту от угона сессии — решайте осознанно.

### Плагин не виден Velocity

```bash
docker compose exec velocity ls -la /server/plugins
```

Если jar на месте, а плагин не загрузился — проверьте, что в архиве есть
дескриптор:

```bash
unzip -p artifacts/kofauth-velocity.jar velocity-plugin.json
```

Пусто — сборка шла без `-proc:full`. Сборщик это проверяет и падает с
объяснением, так что появиться такое может только при сборке в обход `install.sh`.

### Забыт пароль администратора

```bash
./kofauth.sh console
# > auth resetpassword Ник НовыйПароль1
```

### Начать с чистого листа

```bash
./kofauth.sh destroy     # удалит контейнеры, тома и все данные
./install.sh
```

## 13. Чек-лист перед публичным запуском

- [ ] `.env` скопирован **вне сервера** — вместе с `ENCRYPTION_KEY`
- [ ] Резервное копирование настроено **и проверено восстановлением**
- [ ] Порты 3306 и 6379 не открыты в интернет (по умолчанию так и есть)
- [ ] `TRUST_PROXY_HEADER=true` стоит **только** при работающем обратном прокси
- [ ] Кабинет отдаётся по HTTPS, а не по HTTP
- [ ] SMTP настроен — без него нет восстановления пароля
- [ ] Игроку выдана роль `admin`, пароль администратора не совпадает ни с чем ещё
- [ ] `MAX_PLAYERS` и `HEAP_LOBBY` соответствуют железу
- [ ] Проверен вход с другого устройства: приходит ли уведомление

## 14. Добавить ещё один игровой сервер

Один и тот же jar Paper работает и Limbo, и игровым сервером — роль задаёт
переменная `KOFAUTH_PAPER_MODE`. Добавьте службу в `docker-compose.yml`,
взяв за образец `lobby`:

```yaml
  survival:
    image: itzg/minecraft-server:2026.5.4-java21
    restart: unless-stopped
    depends_on:
      lobby: {condition: service_healthy}
    environment:
      <<: *kofauth-env
      KOFAUTH_PAPER_MODE: BACKEND
      KOFAUTH_PAPER_BACKEND_VERIFY_SESSION: "true"
      EULA: "TRUE"
      TYPE: PAPER
      VERSION: ${PAPER_VERSION:-1.21.8}
      MEMORY: 4G
      ONLINE_MODE: "FALSE"
      ENFORCE_SECURE_PROFILE: "FALSE"
      PAPER_VELOCITY_SECRET: ${FORWARDING_SECRET:?}
      SERVER_PORT: "25565"
    volumes:
      - survival-data:/data
      - ./artifacts/kofauth-paper.jar:/plugins/kofauth-paper.jar:ro
    networks: [kofauth]
```

Добавьте том `survival-data:` в конец файла и пропишите сервер в
`config/velocity/velocity.toml`:

```toml
[servers]
limbo-1 = "limbo:25565"
lobby-1 = "lobby:25565"
survival = "survival:25565"
try = ["limbo-1"]
```

`try` менять нельзя: там обязан быть Limbo. Окажись в списке игровой сервер —
игрок на мгновение попал бы на него до того, как отработает маршрутизация.

`verify-session: true` на каждом бэкенде обязателен. Форвардинг Velocity —
первая линия обороны, проверка сессии — вторая: она перехватит того, кто
подключился к порту сервера напрямую.

Затем `./kofauth.sh start`.
