# KoF Network — боты

Монорепозиторий Telegram- и Discord-ботов сети. Заменяет модули
`KoFAuth-Telegram` и `KoFAuth-Discord`.

## Зачем монорепозиторий

У ботов общее почти всё: клиент REST, подписка на события, тексты и
форматирование данных. Различается ровно одно — способ нарисовать меню.
Два отдельных репозитория означали бы две копии клиента API, которые
разойдутся при первой же правке контракта.

```
bots/
├── packages/kofauth_common/     общий код
│   └── kofauth_common/
│       ├── config.py            настройки из окружения
│       ├── api.py               клиент /api/bot
│       ├── events.py            чтение очереди /api/bot/events
│       └── texts.py             тексты, значки и форматирование
├── apps/
│   ├── telegram_bot/            aiogram 3, меню на inline-кнопках
│   └── discord_bot/             discord.py 2, slash-команды и View
├── tests/
└── docker/Dockerfile            один образ на обоих
```

## Как боты связаны с Core

```
игрок ──/telegram──> Velocity ──> Core ──> код + ссылка t.me/бот?start=link_КОД
                                    │
бот ──POST /api/bot/link──> WebAPI ─┘

Core ──> очередь в MySQL ──GET /api/bot/events──> бот ──> сообщение игроку
```

**Прямого доступа к MySQL у ботов нет намеренно.** Логика безопасности —
сроки токенов, порядок проверок, ограничение частоты — существует в одном
экземпляре, внутри Core. Второй её экземпляр на Python неизбежно разошёлся бы
с первым, и расхождение проявилось бы там, где его меньше всего ждут.

Поверхность `/api/bot` защищена общим ключом (`X-Bot-Key`). Ключ, а не JWT,
потому что бот действует не от своего имени и не от имени одного игрока:
он обслуживает всех сразу и опознаёт их по идентификатору мессенджера.
**Пустой ключ выключает `/api/bot` целиком**, а не открывает его.

## Направление привязки

Код выдаётся **в игре** и вводится **в боте**. Обратный порядок сломал бы
модель доверия: если бы код выдавал бот по нику, любой знающий чужой ник
привязал бы к себе чужой аккаунт. Владение игровым аккаунтом доказуемо
только внутри игры.

Привязка ведётся по UUID игрока, а не по нику: ник в сети меняется, UUID нет.

### Привязка в один клик

Код в чате кликабельный: нажатие кладёт его в буфер обмена. Рядом —
ссылка, которая доводит привязку до конца:

- **Telegram** — `t.me/<бот>?start=link_КОД`. Telegram передаёт нагрузку боту
  первым же сообщением, поэтому переход по ссылке **и есть привязка**: игроку
  не приходится ничего переписывать. Нужен `KOFAUTH_TELEGRAM_BOT_USERNAME` —
  без имени бота ссылку не из чего собрать, и останется ручной ввод `/link КОД`.
- **Discord** — ссылка на канал привязки (`KOFAUTH_DISCORD_ACCOUNT_CHANNEL_ID`)
  или приглашение на сервер. Автоматически привязать нельзя: slash-команду
  ссылкой не предзаполнить, такого механизма у Discord нет. Игрок попадает
  в нужный канал и отправляет `/link КОД` — код уже в буфере.

Направление привязки это не меняет: ссылка меняет способ доставки кода, а не
то, кто его выдаёт. Получить код, не имея доступа к игровому аккаунту,
по-прежнему нельзя.

### Код в канале Discord

`discord.yml → link.post-code-to-channel` дублирует выданный код в канал
привязки. **По умолчанию выключено, и это не перестраховка.** Код
предъявительский: кто первым отправит его боту, тот и получит привязку —
личность отправителя код никак не удостоверяет. Опубликованный в канале,
доступном посторонним, он означает, что аккаунт игрока достанется тому, кто
быстрее прочитал сообщение.

Включать имеет смысл только для канала, куда посторонним хода нет: приватного,
с правом чтения у одной роли, либо на время разбирательства.

## Запуск

Через docker-compose сети — обычный путь:

```bash
docker compose --profile bots up -d
```

Локально:

```bash
python -m venv .venv && .venv/bin/pip install -e packages/kofauth_common
.venv/bin/pip install aiogram discord.py
cp .env.example .env   # заполнить токены и BOT_API_KEY
set -a && . ./.env && set +a
python -m telegram_bot
```

## Тесты

```bash
python -m pytest tests -q
```

Покрыты разделение ошибок транспорта и ошибок по существу, устойчивость
разбора событий к мусору в канале и форматирование значений. Работа с самими
API Telegram и Discord не тестируется: она сводится к вызовам библиотек,
а мокать их означало бы проверять моки.

## Настройки

Читаются из окружения — YAML KoFAuth боту не монтируется, чтобы контейнер
бота не получил секреты базы и JWT, которые ему не нужны.

| Переменная | Назначение |
|---|---|
| `KOFAUTH_API_URL` | адрес WebAPI |
| `KOFAUTH_SECURITY_BOT_API_KEY` | ключ `/api/bot`; тот же, что `security.yml → bot-api.key` |
| `KOFAUTH_EVENTS_POLL_SECONDS` | пауза между опросами очереди, когда она пуста |
| `KOFAUTH_PANEL_URL` | адрес личного кабинета для справки |
| `KOFAUTH_TELEGRAM_BOT_TOKEN` | токен от @BotFather |
| `KOFAUTH_TELEGRAM_BOT_USERNAME` | имя бота без собачки; **обязательно** для ссылки-привязки |
| `KOFAUTH_DISCORD_BOT_TOKEN` | токен приложения Discord |
| `KOFAUTH_DISCORD_GUILD_ID` | сервер для мгновенной регистрации команд; пусто — глобально, до часа |
| `KOFAUTH_DISCORD_ACCOUNT_CHANNEL_ID` | канал привязки: туда ведёт ссылка из игры и туда публикуется код |

Оформление — всё необязательное. Без него боты работают так же, просто
выглядят голыми:

| Переменная | Назначение |
|---|---|
| `KOFAUTH_BANNER_URL` | картинка шапки главного меню; должна быть доступна по HTTP — и Discord, и Telegram скачивают её своими серверами |
| `KOFAUTH_BANNER_FILE` | локальный файл вместо ссылки. Понимает **только Telegram**: загружает один раз и дальше пользуется выданным `file_id`. Discord умеет только ссылку |
| `KOFAUTH_DONATE_URL` | страница поддержки сервера: кнопка в меню и строка в профиле |

## Меню

Оба бота построены вокруг одного перерисовываемого сообщения, а не ленты
ответов: у человека всегда один экран, и кнопки прошлых шагов не остаются
нажимаемыми.

- **Telegram** — inline-кнопки, `callback_data` вида `menu:profile`.
  Telegram ограничивает её 64 байтами, поэтому туда кладётся имя экрана,
  а не состояние. При заданном баннере экран — это фотография с подписью, и
  перерисовка идёт через `edit_caption`: `edit_text` на сообщении с картинкой
  Telegram отвергает, текста у такого сообщения нет вовсе. Подпись ограничена
  1024 символами, поэтому длинные экраны обрезаются по границе строки —
  разрыв посреди тега сделал бы разметку незакрытой.
- **Discord** — `discord.ui.View`, ответы эфемерные: профиль и история видны
  только вызвавшему, даже если команда набрана в общем канале. У меню задан
  таймаут, по истечении которого кнопки гасятся, а не остаются выглядящими
  рабочими. Баннер ставится только на главный экран: на каждом подэкране он
  вытеснил бы содержимое за пределы видимого.

Разделы: **Профиль**, **Защита**, **История**, **Сессии**, **Справка**.

Отвязка в обоих ботах спрашивает подтверждение: она выключает второй фактор
и уведомления разом, то есть тихо снижает защиту аккаунта.

### Чего в меню нет

**Устройства.** Раздел показывал те же адреса, что и «История», только в
другом порядке, и ни одного действия к ним не прилагалось — доверить или
заблокировать устройство из бота было нельзя. Смотреть список, с которым
нечего сделать, незачем. Эндпоинт `/api/bot/devices` остался: им пользуется
личный кабинет, где действия есть.

**UUID, статус, адрес и расположение в профиле.** UUID и статус — служебные
поля, игроку они ничего не говорят. Адрес и город — данные, из-за которых
экран профиля нельзя показать другу, не открыв заодно, откуда ты выходишь в
сеть; при этом ни то, ни другое ничем не помогает: адрес входа виден в
«Истории», а разбор чужого входа — задача администратора, у него для этого
есть `/auth player`.

В запросе подтверждения входа адрес и расположение остались, и это не
противоречие: там они отвечают на вопрос «я ли это сейчас захожу», без них
кнопка «Войти» превращается в формальность.

## Оформление

Градиентов ни Telegram, ни Discord в тексте не умеют — у обоих разметка
ограничена жирным, курсивом и моноширинным. Поэтому бренд опознаётся не
цветом, а формой: одно слово `KoFNetwork`, всегда с одним и тем же значком.
Единственное место, где фирменный цвет вообще доступен, — полоса эмбеда
Discord; там стоит красный KoF (`#FF2D2D`).

Значки разделов собраны в `texts.ICON`. Это не украшательство: кнопка в
Telegram и заголовок экрана, на который она ведёт, задаются в разных файлах,
и без общего источника один из них рано или поздно отстаёт от другого.
