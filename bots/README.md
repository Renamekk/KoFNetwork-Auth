# KoF Network — боты

Монорепозиторий Telegram- и Discord-ботов сети. Заменяет модули
`KoFAuth-Telegram` и `KoFAuth-Discord`.

## Зачем монорепозиторий

У ботов общее почти всё: клиент REST, подписка на события, тексты и
форматирование данных. Различается ровно одно — способ нарисовать меню.
Два отдельных репозитория означали бы две копии клиента API, которые
разойдутся при первой же правке контракта.

```
bots/
├── packages/kofauth_common/     общий код
│   └── kofauth_common/
│       ├── config.py            настройки из окружения
│       ├── api.py               клиент /api/bot
│       ├── events.py            чтение очереди /api/bot/events
│       ├── glyphs.py            значки кнопок и фирменные emoji
│       ├── texts.py             тексты и форматирование
│       ├── cards/               графические экраны
│       └── assets/              шрифт, шаблон и готовые картинки
├── apps/
│   ├── telegram_bot/            aiogram 3, меню на inline-кнопках
│   └── discord_bot/             discord.py 2, slash-команды и View
├── tests/
└── docker/Dockerfile            один образ на обоих
```

## Как боты связаны с Core

```
игрок ──/telegram──> Velocity ──> Core ──> код + ссылка t.me/бот?start=link_КОД
                                    │
бот ──POST /api/bot/link──> WebAPI ─┘

Core ──> очередь в MySQL ──GET /api/bot/events──> бот ──> сообщение игроку
```

**Прямого доступа к MySQL у ботов нет намеренно.** Логика безопасности —
сроки токенов, порядок проверок, ограничение частоты — существует в одном
экземпляре, внутри Core. Второй её экземпляр на Python неизбежно разошёлся бы
с первым, и расхождение проявилось бы там, где его меньше всего ждут.

Поверхность `/api/bot` защищена общим ключом (`X-Bot-Key`). Ключ, а не JWT,
потому что бот действует не от своего имени и не от имени одного игрока:
он обслуживает всех сразу и опознаёт их по идентификатору мессенджера.
**Пустой ключ выключает `/api/bot` целиком**, а не открывает его.

## Направление привязки

Код выдаётся **в игре** и вводится **в боте**. Обратный порядок сломал бы
модель доверия: если бы код выдавал бот по нику, любой знающий чужой ник
привязал бы к себе чужой аккаунт. Владение игровым аккаунтом доказуемо
только внутри игры.

Привязка ведётся по UUID игрока, а не по нику: ник в сети меняется, UUID нет.

### Привязка в один клик

Код в чате кликабельный: нажатие кладёт его в буфер обмена. Рядом —
ссылка, которая доводит привязку до конца:

- **Telegram** — `t.me/<бот>?start=link_КОД`. Telegram передаёт нагрузку боту
  первым же сообщением, поэтому переход по ссылке **и есть привязка**: игроку
  не приходится ничего переписывать. Нужен `KOFAUTH_TELEGRAM_BOT_USERNAME` —
  без имени бота ссылку не из чего собрать, и останется ручной ввод `/link КОД`.
- **Discord** — ссылка на канал привязки (`KOFAUTH_DISCORD_ACCOUNT_CHANNEL_ID`)
  или приглашение на сервер. Автоматически привязать нельзя: slash-команду
  ссылкой не предзаполнить, такого механизма у Discord нет. Игрок попадает
  в нужный канал и отправляет `/link КОД` — код уже в буфере.

Направление привязки это не меняет: ссылка меняет способ доставки кода, а не
то, кто его выдаёт. Получить код, не имея доступа к игровому аккаунту,
по-прежнему нельзя.

### Код в канале Discord

`discord.yml → link.post-code-to-channel` дублирует выданный код в канал
привязки. **По умолчанию выключено, и это не перестраховка.** Код
предъявительский: кто первым отправит его боту, тот и получит привязку —
личность отправителя код никак не удостоверяет. Опубликованный в канале,
доступном посторонним, он означает, что аккаунт игрока достанется тому, кто
быстрее прочитал сообщение.

Включать имеет смысл только для канала, куда посторонним хода нет: приватного,
с правом чтения у одной роли, либо на время разбирательства.

## Запуск

Через docker-compose сети — обычный путь:

```bash
docker compose --profile bots up -d
```

Локально:

```bash
python -m venv .venv && .venv/bin/pip install -e packages/kofauth_common
.venv/bin/pip install aiogram discord.py
cp .env.example .env   # заполнить токены и BOT_API_KEY
set -a && . ./.env && set +a
python -m telegram_bot
```

## Тесты

```bash
python -m pytest tests -q
```

Покрыты разделение ошибок транспорта и ошибок по существу, устойчивость
разбора событий к мусору в канале и форматирование значений. Работа с самими
API Telegram и Discord не тестируется: она сводится к вызовам библиотек,
а мокать их означало бы проверять моки.

Отдельно закреплено оформление (`tests/test_buttons.py`): набор стилей Discord
без синего и зелёного, отдельная строка у опасного действия, назначение кнопок
и длина `callback_data` у Telegram, разбор фирменных emoji и откат на обычные.
Раскладка кнопок — чистая функция от состояния, её видно без сети.

Графические экраны закреплены тремя файлами:

- `test_cards.py` — содержимое: настоящие данные аккаунта, сохранённая
  маскировка адреса, прочерк вместо пустоты, число записей по политике показа,
  отпечаток, который меняется вместе с данными и с версией оформления.
- `test_cards_render.py` — сама картинка. Что она получилась, что не весит
  мегабайты и что **всё нарисованное лежит внутри панели** — это сравнение с
  шаблоном, а не с эталонным изображением: эталон пришлось бы обновлять после
  каждой правки отступа, и он проверял бы совпадение с прошлой версией, а не
  пригодность нынешней. Длинные ники, пустые значения и списки от нуля до
  двадцати пяти записей проверяются им же.
- `test_cards_cache.py` и `test_cards_screens.py` — пределы кэша (по числу, по
  объёму, по сроку), одна отрисовка на одновременные запросы, и стык с
  мессенджерами: что сообщение с картинкой не пытаются превратить в текстовое,
  что отказ отрисовки оставляет рабочий экран, а подтверждение входа остаётся
  текстом.
- `test_bot_resilience.py` — поведение при отказах. Ни одна кнопка не выпускает
  наружу недоступность API: экран остаётся рабочим, а человек получает ответ
  вместо «This interaction failed» и бесконечных часов. Отдельно закреплено
  главное свойство подтверждения входа: кнопки убираются только тогда, когда
  сервер действительно записал решение. Невнятный ответ — неверный ключ бота,
  отвергнутый запрос — оставляет их на месте, иначе живой запрос терял бы
  единственный способ довести вход до конца.

## Настройки

Читаются из окружения — YAML KoFAuth боту не монтируется, чтобы контейнер
бота не получил секреты базы и JWT, которые ему не нужны.

| Переменная | Назначение |
|---|---|
| `KOFAUTH_API_URL` | адрес WebAPI |
| `KOFAUTH_SECURITY_BOT_API_KEY` | ключ `/api/bot`; тот же, что `security.yml → bot-api.key` |
| `KOFAUTH_EVENTS_POLL_SECONDS` | пауза между опросами очереди, когда она пуста |
| `KOFAUTH_PANEL_URL` | адрес личного кабинета для справки |
| `KOFAUTH_TELEGRAM_BOT_TOKEN` | токен от @BotFather |
| `KOFAUTH_TELEGRAM_BOT_USERNAME` | имя бота без собачки; **обязательно** для ссылки-привязки |
| `KOFAUTH_DISCORD_BOT_TOKEN` | токен приложения Discord |
| `KOFAUTH_DISCORD_GUILD_ID` | сервер для мгновенной регистрации команд; пусто — глобально, до часа |
| `KOFAUTH_DISCORD_ACCOUNT_CHANNEL_ID` | канал привязки: туда ведёт ссылка из игры и туда публикуется код |

Оформление — всё необязательное. Без него боты работают так же, просто
выглядят голыми:

| Переменная | Назначение |
|---|---|
| `KOFAUTH_BANNER_URL` | картинка шапки главного меню; должна быть доступна по HTTP — и Discord, и Telegram скачивают её своими серверами |
| `KOFAUTH_BANNER_FILE` | локальный файл вместо ссылки. Понимает **только Telegram**: загружает один раз и дальше пользуется выданным `file_id`. Discord умеет только ссылку |
| `KOFAUTH_DONATE_URL` | страница поддержки сервера: кнопка в меню и строка в профиле |
| `KOFAUTH_EMOJI_DISCORD` | фирменные emoji на кнопках Discord, `ключ=<:имя:id>` через запятую |
| `KOFAUTH_EMOJI_TELEGRAM` | фирменные emoji в тексте Telegram, `ключ=id` через запятую |
| `KOFAUTH_CARDS_ENABLED` | графические экраны; `false` — те же экраны текстом |
| `KOFAUTH_CARDS_DIR` | свой каталог ресурсов (`fonts/`, `screens/`) вместо встроенного |
| `KOFAUTH_CARDS_QUALITY` | качество JPEG, по умолчанию 84 |
| `KOFAUTH_CARDS_WORKERS` | сколько карточек рисуется одновременно |
| `KOFAUTH_CARDS_CACHE_ENTRIES`, `KOFAUTH_CARDS_CACHE_MB`, `KOFAUTH_CARDS_CACHE_TTL_SECONDS` | пределы кэша готовых картинок |

Оба `KOFAUTH_BANNER_*` — запасной путь: баннер и шаблон карточек лежат в
ресурсах пакета, и по умолчанию настраивать нечего.

## Меню

Оба бота построены вокруг одного перерисовываемого сообщения, а не ленты
ответов: у человека всегда один экран, и кнопки прошлых шагов не остаются
нажимаемыми.

- **Telegram** — inline-кнопки, `callback_data` вида `menu:profile`.
  Telegram ограничивает её 64 байтами, поэтому туда кладётся имя экрана,
  а не состояние. Экран — это фотография с подписью: перерисовка идёт через
  `edit_media`, когда меняется картинка, и через `edit_caption`, когда только
  текст. `edit_text` на сообщении с картинкой Telegram отвергает, а превратить
  фотографию в текстовое сообщение нельзя вовсе — поэтому подача выбирается по
  тому, чем сообщение уже является. Подпись ограничена 1024 символами, поэтому
  длинные экраны обрезаются по границе строки: разрыв посреди тега сделал бы
  разметку незакрытой.
- **Discord** — `discord.ui.View`, ответы эфемерные: профиль и история видны
  только вызвавшему, даже если команда набрана в общем канале. Картинка
  приезжает вложением и подставляется в эмбед по `attachment://` — наружу она
  нигде не выкладывается. У меню задан таймаут, по истечении которого кнопки
  гасятся, а не остаются выглядящими рабочими.

Разделы: **Профиль**, **Защита**, **История**, **Сессии**, **Справка**.

Отвязка в обоих ботах спрашивает подтверждение: она выключает второй фактор
и уведомления разом, то есть тихо снижает защиту аккаунта.

### Чего в меню нет

**Устройства.** Раздел показывал те же адреса, что и «История», только в
другом порядке, и ни одного действия к ним не прилагалось — доверить или
заблокировать устройство из бота было нельзя. Смотреть список, с которым
нечего сделать, незачем. Эндпоинт `/api/bot/devices` остался: им пользуется
личный кабинет, где действия есть.

**UUID, статус, адрес и расположение в профиле.** UUID и статус — служебные
поля, игроку они ничего не говорят. Адрес и город — данные, из-за которых
экран профиля нельзя показать другу, не открыв заодно, откуда ты выходишь в
сеть; при этом ни то, ни другое ничем не помогает: адрес входа виден в
«Истории», а разбор чужого входа — задача администратора, у него для этого
есть `/auth player`.

В запросе подтверждения входа адрес и расположение остались, и это не
противоречие: там они отвечают на вопрос «я ли это сейчас захожу», без них
кнопка «Войти» превращается в формальность.

## Графические экраны

Разделы показываются картинкой, кнопки под ней остаются родными кнопками
мессенджера. Картинка не заменяет ни навигацию, ни подтверждение входа — она
заменяет чтение четырёх строк текста подряд.

| Экран | Чем рисуется |
|---|---|
| Главное меню | готовая картинка из ресурсов |
| Справка | запечённая заранее, своя на каждую площадку |
| Профиль, Защита, История, Сессии | собираются из ответа `/api/bot` в момент показа |

```
kofauth_common/cards/
├── model.py      что написано на карточке (без единой строчки рисования)
├── theme.py      палитра, разметка, версия оформления
├── pixels.py     значки сеткой из символов
├── canvas.py     кисти: панель, плитки, текст с подгонкой по ширине
├── render.py     три раскладки: поля, список, разделы справки
├── cache.py      кэш готовых картинок с тремя пределами
├── service.py    поток отрисовки, дедупликация, отказоустойчивость
├── assets.py     шрифты, шаблон и готовые экраны
└── build.py      сборка ресурсов; запускается руками и редко
```

**Содержимое отделено от отрисовки** ровно затем, чтобы его можно было
проверить: что маскировка адреса не потерялась, что пустое значение стало
прочерком, а не словом «None», что число записей задаёт политика показа, а не
размер картинки. По изображению это узнать нечем.

### Что и почему не делается во время работы

**Ничего не порождается заново.** Иллюстрация нарисована заранее и лежит в
ресурсах; бот только пишет по ней текст. Обращение к чему бы то ни было
внешнему ради экрана профиля — это и задержка, и зависимость от чужой
доступности там, где её быть не должно.

**Панель не перерисовывается.** Свечение рамки — размытие по всему холсту,
десятки миллисекунд на результат, который никогда не меняется. Панель впечена
в шаблон (`build.py`), во время работы остаются текст и плитки: около 40 мс на
карточку.

**Рисование не в цикле событий.** Отрисовка уходит в пул из двух потоков.
В цикле событий она означала бы, что на эти десятки миллисекунд бот перестаёт
отвечать всем сразу — включая того, кто в этот момент подтверждает вход.

**Одинаковое не рисуется дважды.** Готовая картинка запоминается по отпечатку
содержимого; одновременные запросы одного экрана ждут первого. Telegram выдаёт
`file_id`, и он запоминается тем же ключом — повторная отправка не грузит
ничего.

**Кэш ограничен трижды**: по числу записей, по объёму в байтах и по сроку
жизни. Файлов он не создаёт. Кэш «на каждого игрока» — это утечка с отсрочкой:
она незаметна на десяти людях и валит бота на десяти тысячах, а каталог с
персональными картинками пришлось бы ещё и чистить.

### Что остаётся текстом

Подтверждение входа, предупреждения безопасности, ошибки API, вопрос об
отвязке. Их читают в спешке, пересылают, цитируют и ищут поиском — ни одно из
этих действий не работает с изображением.

У разделов картинка сопровождается короткой подписью: в ней то, что нельзя
прятать внутрь картинки, — предупреждение о блокировке, оговорка «показаны не
все записи», нажимаемые ссылки. Полный текст экрана строится всегда, даже
когда картинка удалась: им бот показывает раздел, если нарисовать или
отправить картинку не вышло.

**Оформление ни в одном месте не является условием работы.** Нет библиотеки
рисования, нет шрифта, нет шаблона, Telegram не принял файл — экран будет
показан текстом, ровно как до картинок.

### Чего на карточке нет

Полных адресов, UUID, токенов, кодов привязки и идентификаторов запросов.
Адреса приходят замаскированными с сервера и здесь не восстанавливаются.
Причина простая: картинку пересылают одним нажатием, и всё, что на ней есть,
рано или поздно оказывается на чужом экране.

Ссылок на карточках тоже нет — ни кабинета, ни доната. Карточка справки лежит
в репозитории и адреса конкретной сети не знает, а в тексте ссылка ещё и
нажимается.

### Ресурсы

Шрифт (Monocraft, SIL OFL 1.1), шаблон и готовые экраны лежат в
`kofauth_common/assets/` — внутри пакета, а не рядом с ним: где установлен
`kofauth_common`, там же и они. Монтировать и копировать нечего.

Пересобираются они руками и редко — когда меняется иллюстрация или тексты
справки:

```bash
python -m kofauth_common.cards.build --menu меню.png --card карточка.png
```

Имя запечённой справки содержит отпечаток её содержимого. Это не украшение:
правка списка команд иначе оставила бы на диске картинку со старым списком, и
заметить это было бы нечем. С отпечатком старый файл просто перестаёт
находиться, и бот рисует справку сам.

## Оформление

Палитра сети — чёрное, белое и красный `#FF2D2D`. Красить кнопки как угодно ни
одна из платформ не даёт: у Telegram все кнопки одного цвета темы, у Discord
стилей ровно четыре и три из них — чужие цвета. Поэтому фирменность держится не
на цвете как таковом, а на системе, одинаковой у обоих ботов.

Значки собраны в `kofauth_common/glyphs.py`. Это не украшательство: кнопка в
Telegram и заголовок экрана, на который она ведёт, задаются в разных файлах,
и без общего источника один из них рано или поздно отстаёт от другого.

### Стили кнопок Discord

| Тир | Стиль Discord | Где |
|---|---|---|
| Главное действие экрана | `danger` — фирменный красный | «Профиль», «Защита», «Как привязать аккаунт», переключатель подтверждения, «Войти» |
| Обычная навигация | `secondary` — ближайший к белому нейтральный | «История», «Сессии», «Выйти со всех устройств», «Отклонить» |
| Возврат и отмена | `secondary` + стрелка `◀️` | «Назад», «Отмена» |
| Опасное действие | `danger` + открытый замок + отдельная строка + подтверждение | «Отвязать», «Да, отвязать» |

**`primary` (синий) и `success` (зелёный) не используются нигде.** Четыре
разных цвета в одном меню читаются как четыре разных приложения, а не как одно.
Кнопка-ссылка («Поддержать сервер») — единственное исключение, и не по выбору:
для ссылок Discord другого стиля не даёт.

Красный у Discord один и на «главное», и на «опасно» — второго нет. Опасное
действие отличается не цветом, а тремя вещами сразу: значком открытого замка,
собственной строкой в раскладке и обязательным подтверждением на следующем
экране. Поэтому на экране защиты «Отвязать» вынесена из общей строки: рядом с
«Выйти со всех устройств» два красных слились бы в один, а промах по соседней
кнопке попадал бы в единственное действие, которое выключает второй фактор.

### Иерархия в Telegram

Цвета там нет вовсе, поэтому те же четыре тира разводятся раскладкой:

- **порядок строк** — сначала главное действие, потом навигация, потом опасное,
  возврат последним;
- **ширина** — главное действие и возврат занимают строку целиком, парная
  навигация идёт по две кнопки в строке; кнопка во всю ширину читается как
  более важная, и это единственный доступный там «акцент»;
- **значок** — один на кнопку, из того же набора, что и у Discord.

### Фирменные emoji

Готовые картинки сети подключаются через окружение и **не придумываются в
коде**: идентификатор выдаёт платформа, выдуманный номер даст пустой квадрат.

```bash
KOFAUTH_EMOJI_DISCORD=profile=<:kof_profile:123…>,security=<:kof_shield:123…>
KOFAUTH_EMOJI_TELEGRAM=brand=5368…,profile=5368…:🧱
```

- **Discord** — значение целиком копируется из клиента: наберите `\:имя:` в
  чате и отправьте. Emoji должен быть доступен боту: либо emoji приложения из
  Developer Portal (работают везде), либо emoji сервера, на котором бот
  состоит. Значок ставится на кнопки; в заголовках эмбедов остаётся обычный.
- **Telegram** — идентификатор документа custom emoji. Работает **в тексте
  сообщений**: надпись кнопки в Bot API — голый текст, сущностей к ней не
  прикладывается, и custom emoji там показать нечем. Право слать custom
  emoji есть не у каждого бота, и узнаётся это только по отказу на отправку —
  тогда бот снимает теги, показывает обычные значки и продолжает работать.
- Вместо идентификатора любой платформе можно дать **просто другой символ**:
  `history=🧭`. Форма `id:символ` задаёт и фирменный emoji, и запасной к нему.

Ничего не задано — показываются значки по умолчанию из `glyphs.FALLBACK`.
Это рабочий вид интерфейса, а не заглушка: фирменные emoji только заменяют
картинки, раскладку и стили они не трогают. Опечатка в переменной пропускается
с предупреждением в журнал, и кнопка остаётся со значком по умолчанию — бот
из-за оформления не падает.
